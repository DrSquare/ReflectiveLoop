## One-line Summary

Meta-Harness searches executable harnesses around frozen LLMs using selective access to prior code, scores, and raw traces; its strongest generalization evidence comes from held-out classification datasets and math evaluations, while TerminalBench-2 is explicitly a same-benchmark discovery experiment. [§§3-4, pp. 4-9](https://arxiv.org/pdf/2603.28052v1#page=4)

## 2. Key Contributions

- Optimizes a whole task harness rather than a prompt alone. A coding-agent proposer can diagnose failures, inspect older candidates, and rewrite retrieval, memory, prompt construction, or orchestration. [§3, pp. 4-5](https://arxiv.org/pdf/2603.28052v1#page=4)
- Tests the feedback interface: code and scores alone, code/scores plus summaries, or code/scores plus raw traces. The full interface produces substantially better search candidates in the classification ablation. This supports the value of trace access in this setting, not a universal claim that summaries always hurt. [Table 3, p. 7](https://arxiv.org/pdf/2603.28052v1#page=7)
- Demonstrates reusable discovered programs, with separate evidence for transfer to new classification datasets, new math problems, and additional base models. [Tables 5-6, p. 8](https://arxiv.org/pdf/2603.28052v1#page=8)

## 3. Methodology and Architecture

For frozen model M and task distribution X, the objective is to maximize expected rollout reward over harness programs H. A minimal outer loop proposes, validates, evaluates, and records candidates; it returns a Pareto frontier when both task quality and context cost matter. It retains evaluated candidates but imposes no fixed parent-selection rule. The proposer is Claude Code with Opus 4.6; candidate harnesses are single-file Python programs with task-specific interfaces. Model weights are not updated. [§3 and Algorithm 1, pp. 4-5](https://arxiv.org/pdf/2603.28052v1#page=4)

The filesystem stores all prior candidate source, scores, and traces. The proposer chooses what to read through terminal tools. The reported 10M tokens are diagnostic information **generated by an evaluation**, not tokens necessarily read in one context window. In the TerminalBench search audit it reads a median 82 files per iteration (range 69-99). [pp. 2-3](https://arxiv.org/pdf/2603.28052v1#page=2); [Appendix A.1, Table 8, p. 15](https://arxiv.org/pdf/2603.28052v1#page=15)

Concrete discovered mechanisms include TF-IDF retrieval with label coverage and contrastive examples for classification; a four-route, subject-sensitive BM25 policy for math; and an environment snapshot added to Terminus-KIRA before the coding agent's first turn. These are distinct domain harnesses, not one universally transferred program. [Appendices B.1-B.3, pp. 18-22](https://arxiv.org/pdf/2603.28052v1#page=18)

Classification search uses 20 iterations and two candidates per iteration. Math search uses 250 problems, 40 iterations, and 109 candidate harnesses. Importantly, GPT-OSS-20B is used during math search and is also one of the five evaluated models: the full text establishes **four additional unseen models**, despite language elsewhere calling all five held out. [§§4.1-4.2, pp. 6-8](https://arxiv.org/pdf/2603.28052v1#page=6)

## 5. Limitations and Future Work

- **Evaluation boundary:** §3 describes withholding test feedback, but §4.3 explicitly makes TerminalBench-2 an exception: search and final evaluation use the same 89 tasks. Manual/regex leakage audits do not make this an untouched test. Treat it as benchmark optimization evidence. [p. 9](https://arxiv.org/pdf/2603.28052v1#page=9)
- **Comparison boundary:** evaluation-count matching is not necessarily matching total tokens, proposer compute, or wall-clock cost. The 7.7-point/4x-context result concerns downstream classification prompts, not total search expenditure. [§4.1, pp. 6-7](https://arxiv.org/pdf/2603.28052v1#page=6)
- **Attribution:** the introductory 6x harness gap is cited motivation from other work, not a new within-paper experiment. The broad claim that it beats every hand-engineered coding harness is contradicted by its own Opus table. [p. 1](https://arxiv.org/pdf/2603.28052v1#page=1); [p. 9](https://arxiv.org/pdf/2603.28052v1#page=9)
- The authors leave sensitivity to other proposer agents and co-evolution with model weights to future work. [§5, p. 10](https://arxiv.org/pdf/2603.28052v1#page=10)

## 7. Glossary

- **Harness:** executable context, memory, retrieval, and control logic surrounding a model.
- **Search set:** tasks whose feedback guides candidate generation/selection.
- **Pareto frontier:** candidates not dominated on both quality and cost.
- **Diagnostic history:** persisted artifacts selectively inspected by the proposer; not one giant prompt.
